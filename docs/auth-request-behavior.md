# Запросы входа и ограничение попыток

## Что установлено 23.10.2026

Пользователь сообщил, что после первого нажатия «Войти» в VK Tea получил «Произведено слишком много попыток входа в этот аккаунт». В установленной до исправления версии `AuthActivity` показывала `error_description` из ответа парольного OAuth-запроса. Локального счётчика, который выдаёт этот текст, нет; открытие формы само запрос не отправляет.

Одновременно в клиенте найдены дефекты, способные создавать дополнительные запросы: каждое нажатие запускает отдельный поток, возврат из проверки повторяет парольный вход независимо от `resultCode`, а повторный callback VK ID может повторно обменивать одноразовый код. Эти дефекты подтверждены исходниками. Они не доказывают причину серверного отказа именно на первой попытке данного аккаунта, устройства или сети.

В [схеме ошибок VK](https://github.com/VKCOM/vk-api-schema/blob/master/errors.json) есть отдельная ошибка ограничения попыток авторизации `1105`. Конкретный код ответа пользователя не получен: сырые журналы авторизации и учётные данные не собирались. Вход для диагностики не повторялся. Срок и условия снятия серверного ограничения не установлены.

## Изменения клиента

- `AuthAttemptViewModel` допускает один активный запрос в процессе; кнопки и поля блокируются на время работы. Состояние и необработанный результат переживают пересоздание Activity, результат забирается один раз. Завершённая Activity не получает отложенные диалоги или новую сессию.
- Возврат или отмена страницы проверки не отправляет пароль снова. Продолжение требует отдельного нажатия пользователя; успешность проверки клиент не угадывает по факту возврата.
- `AuthHttpClient` использует отдельный OkHttp без восстановления соединения и переходов по redirect. Также исключён автоматический повтор `503 + Retry-After: 0`; HTTP/1.1 исключает повтор, связанный с объединением HTTP/2-соединений и ответом 421. Деталь поведения библиотеки проверена по [исходникам OkHttp 4.12](https://github.com/square/okhttp/blob/parent-4.12.0/okhttp/src/main/kotlin/okhttp3/internal/http/RetryAndFollowUpInterceptor.kt).
- Ответы ограничения распознаются по HTTP 429, известным кодам и категориям OAuth. Показывается фиксированный текст без таймера, обещающего разблокировку. Повторов по таймеру нет.
- Обмен VK ID использует тот же координатор. Сохранённый PKCE verifier удаляется при принятии запроса; повторный callback не запускает ещё один обмен. При повороте экрана продолжается существующий запрос.
- Удалено журналирование полного ответа OAuth, URL callback, кода, state и текста страниц проверки. Исключения транспорта не передаются в UI или журнал. Диагностика не должна включать пароль, токен, signing secret, trusted hash или содержимое страниц.
- При успешном парольном входе signing secret из ответа сохраняется через существующий контракт `Session.save(..., secret)`.

URL, тип парольного запроса, идентификатор клиента, scope и версия API сохранены. Защита от повторов исправляет управление попытками; доступность legacy OAuth-потока сервером VK она не подтверждает и ограничение сервера не снимает.

23.10.2026 интегрированы изменения Даниила из `origin/main` (`1c85679`, `a28fc28`): парольный запрос использует его порядок `scope`, `client_id`, `client_secret`, `v`, `2fa_supported=1`, `lang`, `libverify_support=1`, `grant_type`, `username`, `password`, затем доступные `trusted_hash` и captcha-параметры. В `AuthHttpClient.password` добавлен тот же VK User-Agent. Наш транспорт уже использовал OkHttp и сохранял signing secret: эти части объединены с существующим координатором и запретом автоматических повторов. Полные ответы OAuth не журналируются. Успешный живой вход на этой объединённой сборке не проверялся.

## Проверка

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Тесты используют синтетические ответы и loopback-сервер на `127.0.0.1`. Проверяются двойные нажатия, поворот экрана, отмена/возврат проверки, одноразовое получение результата, общий запрет параллельных запросов, HTTP 429/503/302 и разрыв соединения без повтора. Реальные серверы авторизации и аккаунты в этих проверках не используются.
