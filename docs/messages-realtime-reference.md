# Сообщения: соответствия референсу и границы проверки

Референс — локальный декомпил Coffee 8.09 (2021), `vk-tea-reference/jadx-code/sources/su/operator555/vkcoffee/`. Его исходники в репозиторий не включены; наличие поведения в старом клиенте не подтверждает доступность API сегодня. Реализация Tea написана заново.

| Сценарий | Что видно в Coffee | Реализация Tea и отличия |
| --- | --- | --- |
| Long Poll | `LongPollService:297,1684`: `messages.getLongPollServer(use_ssl=1)`, затем `act=a_check`, `key`, `ts`, `wait=25`, `mode=234`, `version=1`. После разрыва есть отдельный `messages.getLongPollHistory(pts, photo_sizes=1, fields, msgs_limit=250, events_limit=5000)` (`:806`). | `MessageLongPoll`: `lp_version=3`, `use_ssl=1`, опрос `wait=25`, `mode=2`, `version=3`. По изменению обновляет данные с сервера; новый курсор сопровождается обновлением состояния. Это не полное воспроизведение обработки событий и восстановления истории Coffee. Соединение поддерживается только пока есть активные экраны-подписчики. |
| Счётчик и статусы | `LongPollService:297` получает счётчики вместе с сервером; `:1803–1819` содержит ветви событий онлайн/офлайн и набора текста. | Tea после событий повторно читает `account.getCounters(filter=messages,notifications)`, список диалогов и историю чата. Набор текста не показывается; реакции и уведомления при закрытом приложении не заявлены. |
| Пересылка | `api/messages/MessagesSend:20–54`: `peer_id` для личного диалога или `chat_id` для беседы, `forward_messages`, `random_id`, при необходимости `attachment`. | `MessageForwarder` отправляет ID выбранного сообщения с `forward_messages`, получателем и новым `random_id`; фактическое разрешение метода и доставка зависят от токена и VK. |
| Фотография | `upload/MessagesPhotoUploadTask:40–88`, `api/photos/PhotosSaveMessagesPhoto`: `photos.getMessagesUploadServer`, multipart `photo`, затем `photos.saveMessagesPhoto(server,photo,hash)` и первый объект массива ответа. | `ChatFileSender` использует ту же последовательность, также указывает `peer_id` при получении сервера. Выбранный файл отправляется после подтверждения. JPEG/PNG идут как фотографии; прочие файлы — как документы. |
| Документ | `upload/DocumentUploadTask:53–103`, `api/docs/DocsSave`: поле multipart `file`, затем `docs.save(file)`; декомпил ожидает массив в `response`. | Tea использует `docs.getMessagesUploadServer(type=doc,peer_id)`, multipart `file`, `docs.save(file,title)`; принимает современный объект `response.doc` и старый массив. |
| Голосовое | `upload/AudioMessageUploadTask:65–66` получает `docs.getUploadServer(type=audio_message)`, затем наследует загрузку документа. `attachments/DocumentAttachment:187` формирует `doc{owner}_{id}[_access_key]`. `attachments/Attachment:148–156` распознаёт старую форму `doc.preview.audio_msg`. | Tea получает `docs.getMessagesUploadServer(type=audio_message,peer_id)`, загружает Ogg/Opus, вызывает `docs.save(file)` и отправляет `doc{owner}_{id}[_access_key]`. Принимаются современный `response.audio_message` и старый массив документов с `preview.audio_msg`. Запись требует Android 10+ и работающий Opus-кодер. |
| Проигрывание голосового | `attachments/AudioMessageAttachment:252–267` при отсутствии файла обновляет ссылки через `docs.getById`; управление и прогресс связаны с сервисом плеера. | Tea проигрывает HTTPS-ссылку из истории, с паузой и перемоткой в диалоге; отсутствующую или истёкшую ссылку пока не обновляет через `docs.getById`. |

Дополнительный источник по современным типам ответов — [схема методов VK](https://github.com/VKCOM/api-schema-typescript/blob/master/src/methods/docs.ts): `docs.getMessagesUploadServer` поддерживает `audio_message` и `doc`, `docs.save` описывает объект с `audio_message` или `doc`. Схема относится к другой версии API; фактическая форма ответа на используемой Tea версии 5.82 должна быть проверена отдельно.

Проверки сборки и синтетические тесты не подтверждают получение реальных событий, работу микрофона, права токена, доставку или серверную совместимость. Сетевые отправки выполняются только по явному действию пользователя; после потери связи результат последней отправки может быть неизвестен.
