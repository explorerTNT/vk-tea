# Аудиоплеер

Модуль написан на Java 17 и использует Media3 1.5.1, compileSdk 35 и AGP 8.7.3. Версия Media3 закреплена для текущего инструментария; SDK/AGP и библиотеку следует обновлять совместно. Один ExoPlayer принадлежит `AudioPlaybackService`; список, общий мини-плеер и полноэкранный экран подключаются к нему через MediaController.

## Интерфейс

Внешний вид воспроизводит основные элементы четырёх переданных скриншотов Coffee от 23.10.2026: два состояния списка, полноэкранный плеер и раскрытое меню. Это визуальные референсы, а не демонстрационные данные: названия, исполнители, длительности и качество берутся из выбранных файлов. Точные исходники разметки, обработчиков и PNG перечислены в [карте референса](reference-map.md).

### «Мои аудиозаписи»

- Белый список, синяя строка «Перемешать все» высотой 60 dp и тонкий разделитель. Строки треков имеют минимальную высоту 68 dp; название — 16 sp, исполнитель — 14 sp, длительность справа — 12 sp. При увеличенном шрифте строка может стать выше.
- У текущего трека слева появляется синий индикатор из трёх полос; название сохраняет обычный тёмный цвет. Значок со стрелкой относится к распознанному локальному источнику, а не к отметке «Сохранить». Неизвестный `content`-провайдер не считается доказательством наличия файла на устройстве.
- Нажатие трека выбирает его в общей очереди, запускает воспроизведение и открывает полноэкранный плеер. Долгое нажатие открывает действия именно для выбранной строки.
- «Перемешать все» включает shuffle, выбирает случайную начальную позицию и запускает очередь. Локальный фильтр не меняет порядок воспроизведения или индексы треков в сервисе.
- Нажатие заголовка открывает «Мои аудиозаписи / Добавить аудиофайлы / Очистить очередь». Очистка останавливает плеер и удаляет очередь. Кнопка поиска в toolbar фильтрует существующую очередь по названию и исполнителю; сетевой поиск не выполняется.
- В пустом списке есть пояснение и ссылка «Добавить аудиофайлы». Импорт использует системный `ACTION_OPEN_DOCUMENT` для нескольких документов `audio/*`. Крупной встроенной панели Media3 и технических кнопок над списком больше нет.

Сейчас список показывает импортированные документы из очереди сервиса. Это не полный каталог аудио VK и не сканирование всей медиатеки устройства. Первый импорт в пустую очередь начинает играть; добавление в непустую очередь сохраняет текущую позицию и состояние паузы.

### Общий мини-плеер

`AudioMiniPlayerView` находится в `MainActivity`, поэтому переключение основных разделов не создаёт отдельный плеер и не очищает очередь. Компактная белая панель показывает заглушку обложки, название, исполнителя и play/pause. Нажатие текстовой части открывает `AudioPlayerActivity`; без текущего трека панель скрыта. Список не содержит второй копии этой панели.

### Полноэкранный плеер и меню

Вверху — тёмная область обложки с музыкальной заглушкой и кнопкой сворачивания. На границе расположены seek bar, прошедшее и полное время. Ниже — название, исполнитель и доступные реальные сведения о битрейте/размере; затем основные действия «Сохранить», предыдущий, play/pause, следующий, очередь. Нижний ряд содержит управление звуком, shuffle, repeat, экспорт файла и меню.

Сворачивание закрывает экран, сохраняя воспроизведение. Repeat переключается между off/all/one; shuffle отражает состояние сервиса. Для небольших экранов блок управления прокручивается; при горизонтальной ориентации обложка и управление располагаются рядом. Это поведение реализации, не утверждение о завершённой проверке всех размеров экранов.

Системное transport-уведомление теперь открывает **полноэкранный `AudioPlayerActivity`**, а не раздел списка. Session/player остаются теми же.

Меню повторяет порядок действий на референсе, но доступность соответствует реализованным возможностям:

| Действие | Поведение VK Tea |
| --- | --- |
| Сохранить | Только локальная отметка в `audio_marks` по непрозрачному mediaId. Не добавляет трек в VK, не скачивает файл и не создаёт кеш |
| Скачать аудиозапись | Для доступного `content`-документа — копирование байтов в новый документ, выбранный пользователем через SAF. Удалённые HTTPS-источники пока не скачиваются |
| Текст песни / Показать похожие / Искать исполнителя | Отключены: соответствующие API-потоки ещё не подключены |
| Копировать название | Копирует исполнителя и название, без исходного URI |
| Удалить | Убирает трек из текущей очереди; исходный файл и библиотеку VK не меняет |
| Поделиться | Системный выбор приложения для передачи текста «исполнитель — название» |

Экспорт выполняется в рабочем потоке через `AudioExportActivity`. Сначала пользователь выбирает место с `ACTION_CREATE_DOCUMENT`; отмена не запускает копирование. Исходный документ не перезаписывается: проверяются совпадение документов и пустое назначение. Провайдер может отказать в чтении/записи или не поддерживать нужный режим назначения; в таком случае показывается ошибка без раскрытия URI.

## Метаданные и состояние

`AudioFragment` читает `OpenableColumns.DISPLAY_NAME/SIZE` и теги `MediaMetadataRetriever` в отдельном потоке: title, artist, duration, bitrate. Если тегов нет, остаются имя документа и обозначение локального файла; неизвестные длительность, битрейт и размер не подменяются вымышленными значениями.

Сервис сохраняет только три положительных числовых extras типа Long:

| Ключ `AudioUi` | Единицы |
| --- | --- |
| `EXTRA_DURATION_MS` | Миллисекунды |
| `EXTRA_BITRATE` | Биты в секунду |
| `EXTRA_FILE_SIZE` | Байты |

Остальные входные extras и произвольные artwork/DRM/ads/subtitle URL не пересылаются. Полноэкранный UI умеет читать доступные встроенные байты обложки или локальный `content`-источник в фоне; в текущем узком сервисном контракте произвольная обложка из входного MediaItem удаляется, поэтому обычный импорт может показывать заглушку. Сетевые URL обложек этот экран не загружает.

Импортированный документ получает стабильный mediaId `AudioUi.mediaId(uri)` на основе SHA-256: исходный URI не становится публичным идентификатором. Соответствие идентификатора исходному документу хранится только внутри процесса для локальных действий. Отметку «Сохранить» можно снова сопоставить с тем же URI при повторном импорте.

Очередь, repeat/shuffle и позиция живут в памяти сервиса. После завершения процесса или перезагрузки они не восстанавливаются; автоматического фонового старта нет. Постоянные URI-гранты не накапливаются. Состояние запроса поиска и ещё не обработанные URI выбора сохраняются при пересоздании фрагмента; завершившаяся фоновая загрузка не передаёт документы отключённому контроллеру.

## Сервис и контракт подключения

`AudioPlayback.connect(context[, listener])` возвращает `ListenableFuture<MediaController>`. Вызывать с главного потока, обрабатывать ошибку подключения и `onDisconnected`. Каждый UI освобождает свой future через `MediaController.releaseFuture` в `onStop`, даже если подключение ещё не завершилось; контекст Activity в сервисе не сохраняется.

Закрытие экрана или уход в другое приложение освобождает только UI-контроллер. При удалении задачи активное воспроизведение продолжается, неактивное останавливается. MediaSession передаёт Android метаданные и транспортные команды; Media3 управляет audio focus и приостанавливает воспроизведение при `AUDIO_BECOMING_NOISY`.

Для следующего модуля каталога подключённый контроллер предоставляет стандартный Player Media3:

```java
MediaItem track = new MediaItem.Builder()
        .setMediaId("audio:owner_track") // стабильный неприватный идентификатор
        .setUri(readyHttpsUri)           // готовый HTTPS URL либо доступный content URI
        .setMediaMetadata(new MediaMetadata.Builder()
                .setTitle(title)
                .setArtist(artist)
                .build())
        .build();
controller.setMediaItem(track);
controller.prepare();
controller.play();
```

Полная замена очереди: `controller.setMediaItems(tracks, selectedIndex, 0)`; добавление без сброса текущей позиции: `controller.addMediaItems(tracks)`.

Весь запрос проверяется до передачи ExoPlayer. Разрешены иерархические `content://` и корректные `https://` без userinfo; HTTP, file, data и некорректные адреса отклоняются. URI-образные mediaId заменяются непрозрачными идентификаторами. Кроме разрешённых числовых extras, из входного metadata сохраняются только отображаемые текстовые поля.

Сервис принимает собственный UID приложения и доверенные системные контроллеры. Только собственный UID может поставлять или менять media items; сторонним доверенным контроллерам доступны транспортные команды. Имя пакета само по себе не подтверждает принадлежность приложению. После отзыва авторизации команды отклоняются.

`Session.clear(context)` вызывает `AudioPlayback.stop(context)` и очищает очередь/session/player даже при связанном UI. Этот вызов обязателен: на Android до 11 `SharedPreferences.clear()` не уведомляет слушателя. Дополнительный наблюдатель сервиса обрабатывает удаление токена и поддерживаемые платформой уведомления об очистке. Stop передаётся через receiver с `RECEIVER_NOT_EXPORTED` и не запускает отсутствующий сервис.

## Границы этапа

Музыкальный API VK, обновление истёкших ссылок, локальный прокси, управляемый офлайн-кеш и сетевое скачивание ещё не реализованы. Вызовы `audio.get`, сетевого поиска, lyrics/similar/artist и изменение аудиобиблиотеки аккаунта этот UI не выполняет. Контракт принимает готовые HTTPS-адреса, но это не подтверждает воспроизведение аудио VK.

Интерфейс сопоставлен с предоставленными скриншотами и локальным Coffee-референсом. Обновление установлено на Pixel с сохранением данных; прослушивание на телефоне и приёмка на реальном аккаунте VK не проводились. Попыток входа при установке не выполнялось.

Историческая проверка ядра 22.10.2026: в отдельном чистом эмуляторе API 37 были проверены два синтетических WAV через системный picker, очередь, PLAYING с растущей позицией, системные pause/next/play и продолжение на домашнем экране. `dumpsys activity services` подтвердил `isForeground=true`, тип `mediaPlayback` и transport-уведомление. Эмулятор работал без вывода звука. Этот результат относится к прежнему экрану ядра и не подменяет проверку новой UI-редакции.

Ручной сценарий для нового UI: импортировать два тестовых файла; проверить строку shuffle, локальный поиск, выбор/долгое нажатие трека, мини-плеер в другом разделе, полноэкранные pause/seek/next/repeat, сворачивание и переход из уведомления; затем локальную отметку, отмену и завершение SAF-экспорта, очистку очереди и выход из аккаунта. Отдельно проверяются маленький экран, горизонтальная ориентация, увеличенный шрифт, физическая гарнитура, Bluetooth, звонок, локскрин и OEM-ограничения фона.
