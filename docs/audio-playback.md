# Ядро аудиоплеера

Первый самостоятельный модуль аудио: Java 17, Media3 1.5.1, существующие compileSdk 35 и AGP 8.7.3. Версия Media3 закреплена для текущего инструментария проекта; обновление SDK/AGP и библиотеки следует делать совместно.

## Что работает

- «Аудиозаписи» → «Открыть аудиофайлы»: системный выбор нескольких документов `audio/*`. Выбор добавляется в очередь; первая непустая очередь начинает играть. Добавление к существующей очереди сохраняет её текущую позицию и состояние паузы.
- Выбор трека, play/pause, предыдущий/следующий трек, перемотка, repeat one/all и shuffle. «Очистить» останавливает воспроизведение и удаляет очередь.
- Один ExoPlayer принадлежит foreground-сервису; закрытие экрана или уход в другое приложение освобождает только UI-контроллер. При удалении задачи активное воспроизведение продолжается, неактивное останавливается.
- MediaSession передаёт Android метаданные и команды для системного уведомления, экрана блокировки и гарнитуры. Нажатие уведомления открывает «Аудиозаписи». Media3 управляет audio focus и приостанавливает воспроизведение при `AUDIO_BECOMING_NOISY`.
- Выход из аккаунта очищает очередь и освобождает session/player до уничтожения сервиса, даже если UI ещё связан с ним.

## Контракт для следующих модулей

`com.vktea.audio.AudioPlayback.connect(context[, listener])` возвращает `ListenableFuture<MediaController>`. Вызывать с главного потока, обрабатывать ошибку подключения и `onDisconnected`. UI должен вызвать `MediaController.releaseFuture(future)` в `onStop`, в том числе если подключение ещё не завершилось. Контекст Activity в сервисе не сохраняется.

Подключённый контроллер реализует обычный `Player` Media3:

```java
MediaItem track = new MediaItem.Builder()
        .setMediaId("audio:owner_track") // стабильный неприватный идентификатор
        .setUri(readyHttpsUri)           // готовый HTTPS URL либо content URI с правом чтения
        .setMediaMetadata(new MediaMetadata.Builder()
                .setTitle(title)
                .setArtist(artist)
                .build())
        .build();
controller.setMediaItem(track);
controller.prepare();
controller.play();
```

Для полной очереди используется `controller.setMediaItems(tracks, selectedIndex, 0)`; для добавления без сброса текущей позиции — `controller.addMediaItems(tracks)`.

Весь запрос очереди проверяется до передачи ExoPlayer. Разрешены иерархические `content://` и корректные `https://` без userinfo; HTTP, file, data и некорректные адреса отклоняются. URI-образные mediaId заменяются непрозрачными идентификаторами. Из входного metadata сохраняются только отображаемые текстовые поля; extras, artwork, DRM, ads и subtitle URL не переносятся. Поддержка обложек может быть добавлена отдельным проверяемым контрактом.

Сервис принимает собственный UID приложения и доверенные системные контроллеры. Только собственный UID может поставлять или менять media items; сторонним доверенным контроллерам доступны транспортные команды. Имя пакета само по себе не подтверждает принадлежность приложению. После отзыва авторизации команды отклоняются.

`Session.clear(context)` вызывает `AudioPlayback.stop(context)`. Этот вызов обязателен: на Android до 11 `SharedPreferences.clear()` не уведомляет слушателя. Дополнительный наблюдатель сервиса обрабатывает удаление токена и поддерживаемые платформой уведомления об очистке. Stop передаётся через receiver с `RECEIVER_NOT_EXPORTED` и не запускает отсутствующий сервис.

## Границы текущего этапа

Музыкальный API VK, обновление истёкших ссылок, прокси, управляемый кеш, скачивание и UI плеера Coffee пока отсутствуют. Локальные документы дают проверяемый источник до подключения каталога. Сетевой контракт принимает уже готовый адрес; воспроизведение VK-аудио этим этапом не подтверждено.

Очередь, repeat/shuffle и позиция живут в памяти сервиса. После остановки процесса или перезагрузки они не восстанавливаются; автоматического фонового старта нет. Чтение документов предоставляется системным picker без общего разрешения на медиатеку; постоянные URI-гранты не накапливаются, поскольку восстановления после перезагрузки пока нет.

Полноэкранный UI 1:1, мини-плеер меню и сохранение предпочтений остаются следующими задачами. Текущий экран — функциональная точка входа к ядру.

## Проверка

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Robolectric API 28 проверяет границы доверия, невозможность подменить очередь внешним контроллером, отклонение всего запроса при некорректном источнике, удаление приватных request metadata, отзыв авторизации, остановку связанного сервиса, очистку неактивной задачи и восстановление раздела при пересоздании Activity.

22.10.2026 в отдельном чистом эмуляторе API 37 проверены выбор двух синтетических WAV через системный picker, очередь из двух треков, состояние PLAYING с растущей позицией, системные pause/next/play и продолжение воспроизведения на домашнем экране. `dumpsys activity services` подтвердил `isForeground=true`, тип `mediaPlayback` и transport-уведомление. Эмулятор запущен без вывода звука; эти проверки подтверждают декодирование и состояние сервиса, прослушивание на физическом устройстве не проводилось. UI панели управления проверен по скриншоту.

Для ручной проверки: войти, выбрать два тестовых аудиофайла, проверить переключение/паузу/перемотку, уйти на домашний экран и управлять воспроизведением из уведомления. Затем вернуться, очистить очередь и проверить выход из аккаунта во время воспроизведения. Физическую гарнитуру, Bluetooth, прерывание звонком, локскрин и OEM-ограничения фоновых процессов проверять отдельно на телефоне.

Использованные контракты: [MediaSessionService и фон](https://developer.android.com/media/media3/session/background-playback), [MediaController и его освобождение](https://developer.android.com/media/media3/session/connect-to-media-app), [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files).
